## Repository review, 8 October 2026

The follow-up review starts at `78980a1` and covers the repository entry points, interruption handling,
installation, documentation, links, artifact access and tracked-file hygiene. It does not repeat the full
training or inference study.

Three operational faults were corrected:

* A batch task with only `scores.json` could be counted as complete after interruption. Completion now
  requires a matching task identity and all four output hashes in an atomically written `complete.json`.
  A replacement run clears the old record before inference; incomplete or damaged results are rerun.
* A misspelled `prepare-cases --config` could return success without preparing a case. It now raises an
  error. Artifact groups, NUTS case names and batch shard ranges are also validated.
* `nuts-verify` previously printed differences without failing. It now verifies the ten input file hashes
  per case, checks diagnostics, scores and the convergence gate, and returns a nonzero status on failure.
  Score tolerances are explicit CLI options.

The README distinguishes packaged table checks from commands requiring model assets. The monitoring input
count is corrected to 1,104 test files plus 49 pilot files. The older numerical validation remains dated
separately, and the unresolved CPU pressure comparison is stated in the README and reproduction guide.
